# 10.445. Межскладской transfer / in_transit вне MVP

## Решение

Для MVP PACK.IT CRM Next отдельный межскладской workflow `transfer / in_transit` не вводится.

Базовая эксплуатационная модель MVP предполагает один склад.

- выезд оборудования на мероприятие оформляется складской операцией `issue`;
- возврат оборудования с мероприятия оформляется складской операцией `return`;
- перемещение между несколькими самостоятельными складами, филиалами или постоянными внешними базами не является обязательным сценарием MVP;
- оборудование на площадке не трактуется как `in_transit` между складами.

## Архитектурное следствие

Текущая модель не должна жёстко запрещать появление нескольких складов в будущем, но отдельные статусы, документы и транзакционный workflow межскладского перемещения не реализуются до появления реальной продуктовой необходимости.

При будущем расширении стандартный WMS-процесс `transfer -> in_transit -> receipt at destination` должен добавляться отдельным warehouse use case, без изменения уже принятой модели `issue / return` для мероприятий.

## Причина

Для техпродакшна с одним основным складом межскладской transfer-flow не является повседневной операцией и в MVP только усложнил бы интерфейс, состояния и учёт. Каноническими физическими операциями для выездного оборудования остаются выдача и возврат.
