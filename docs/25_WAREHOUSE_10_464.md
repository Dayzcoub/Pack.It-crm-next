# 10.464. Субаренда заменяет собственный резерв на выбранное количество

## Решение

Если менеджер сознательно использует субаренду при наличии собственного оборудования, соответствующее количество собственного оборудования **не резервируется** под этот проект.

Субаренда в этой части заменяет собственное обеспечение проекта, а не создаёт дополнительный страховочный резерв из нашего склада.

## Правила

- потребность позиции проекта может быть разделена между собственным обеспечением и субарендой;
- количество, закрытое субарендой, не должно одновременно резервироваться из собственного `inventory`;
- собственное оборудование, которое не требуется для оставшейся части потребности проекта, остаётся доступным для других проектов;
- подтверждённая субаренда закрывает свою часть проектной потребности согласно уже принятой модели `subrent`;
- двойного обеспечения одной и той же части потребности быть не должно;
- склад PACK.IT по-прежнему учитывает только собственное оборудование и не включает субаренду в складские остатки.

## Пример

Проекту нужно 10 приборов.

Менеджер решил обеспечить:

- 6 — собственным оборудованием;
- 4 — подтверждённой субарендой.

В результате PACK.IT резервирует из собственного склада только 6 приборов. Остальные 4 собственных прибора, если они доступны, остаются свободными для других проектов.

## Смысл для MVP

Субаренда является полноценным способом проектного обеспечения, а не страховкой поверх собственного резерва. Это не создаёт скрытого двойного резервирования и позволяет менеджеру осознанно распоряжаться собственным парком между параллельными проектами.
