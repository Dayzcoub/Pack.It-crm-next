# Документация PACK.IT CRM Next

Эта папка является основным местом хранения продуктовой, архитектурной и технической документации PACK.IT.

## Зачем нужна эта документация

Новая версия PACK.IT должна разрабатываться не как набор случайно нарастающих блоков, а как заранее описанная система:

- с понятной главной сущностью;
- с разделением продукта на модули;
- с нормальными ролями и доступами;
- с отдельной системной админкой;
- с подключаемым 3D-конструктором;
- с понятным складским контуром;
- с контролируемой генерацией документов;
- с возможностью развивать приложение без архитектурного хаоса.

## Главная сущность

Главная сущность приложения — **Проект / Смета**.

3D-конструктор, складской контур, документы, команда, транспорт, клиенты и статусы существуют вокруг проекта, а не заменяют его.

Проект формирует потребность, но остатки, резервы, дефициты, субаренда и складские движения остаются источниками истины в собственных продуктовых контекстах.

Файлы `25_WAREHOUSE_10_xxx.md` являются атомарными decision notes. Их складские термины трактуются через канонические границы `05_INVENTORY_RESERVATIONS.md`.

## Принятая техническая база

PACK.IT проектируется как:

```text
модульный монолит
+ progressive DDD-lite
+ shared API contracts
+ PostgreSQL как источник истины
+ автоматическая architecture check
```

Складской интерфейс может быть единым, но backend-разделение обязательно:

```text
catalog
inventory
reservations
shortages
subrent
warehouse-operations
```

Конкретный runtime, framework, ORM, auth-provider и production-провайдер пока не выбраны и должны приниматься отдельными ADR.

## Правило ведения документации

Все важные решения по PACK.IT должны переноситься из чата в документы.

Если в обсуждении появляется новое архитектурное решение, оно должно быть зафиксировано в одном из документов или вынесено в отдельный новый документ.

Если терминология раннего decision note конфликтует с более поздним каноническим доменным документом, ранний файл должен быть обновлён или явно перепривязан, а не оставлен как равноправная архитектурная версия.
