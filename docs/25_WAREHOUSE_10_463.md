# 10.463. Субаренда может использоваться как осознанное проектное решение

## Решение

В PACK.IT субаренда допускается не только как способ закрыть фактический дефицит собственного оборудования.

Менеджер может сознательно использовать субаренду для конкретной позиции проекта даже тогда, когда собственного оборудования формально достаточно.

Типовые причины:

- сохранить собственный парк под другой проект;
- взять у подрядчика конкретный комплект или модель;
- не разбирать уже собранный комплект собственного оборудования;
- упростить логистику проекта;
- использовать оборудование поставщика, которое удобнее доставить напрямую на площадку.

## Правила

- субаренда остаётся ресурсом конкретного проекта и не становится складским остатком PACK.IT;
- такое решение не требует искусственно создавать `ShortageCase`, если реального дефицита собственного оборудования нет;
- подтверждённая субаренда должна содержать поставщика, количество, цену и согласованные условия доставки;
- её стоимость участвует в экономике проекта по уже принятой модели;
- если субаренда заменяет использование части собственного оборудования, соответствующая собственная потребность проекта не должна одновременно считаться и обеспеченной своим складом, и закрытой субарендой;
- история изменений субаренды сохраняется.

## Смысл для MVP

Субаренда — это не только аварийный механизм для дефицита, а обычный проектный инструмент менеджера. При этом складская модель не усложняется: внешний ресурс остаётся в контексте проекта и `subrent`, а не попадает в `inventory`.
