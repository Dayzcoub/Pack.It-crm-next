# 10.448. Отдельный `receipt` workflow не входит в MVP

## Решение

Для MVP PACK.IT отдельный пользовательский процесс складской приёмки `receipt` не вводится.

При создании новой складской позиции или добавлении новой складской единицы её начальное количество может сразу становиться частью `on_hand`.

Это решение принято сознательно для техпродакшн-сценария с одним складом и минимальным операционным контуром: отдельный документ приёмки, статусы входящей поставки и этап подтверждения поступления пока не нужны.

## Совместимость с общими правилами складского учёта

Решение не отменяет инварианты 10.432, 10.433 и 10.435:

- применённые складские изменения остаются неизменяемыми;
- изменение количества должно иметь прослеживаемое основание;
- прямое произвольное редактирование текущего остатка не является нормальной бизнес-операцией.

Поэтому первоначальное появление количества оформляется внутри use case создания/добавления складского запаса и записывается в операционную историю как начальное поступление/инициализация запаса с использованием общего `WarehouseOperation` envelope. Отдельного пользовательского `receipt` workflow и отдельного экрана приёмки для этого не требуется.

После создания позиции текущее `on_hand` нельзя произвольно переписывать. Ошибки исправляются отдельной `inventory adjustment` операцией, а списание, выдача и возврат выполняются соответствующими типизированными складскими операциями.

## MVP

В MVP:

- нет отдельного `receipt` процесса;
- нет входящих поставок со статусами `expected / arrived / received`;
- новое оборудование может быть заведено сразу как находящееся на складе;
- факт первоначального появления количества остаётся прослеживаемым в истории операций;
- если позднее появится реальная потребность в закупках, поставщиках и многоэтапной приёмке, стандартный `receipt` workflow может быть добавлен без изменения базовой модели `inventory`.
