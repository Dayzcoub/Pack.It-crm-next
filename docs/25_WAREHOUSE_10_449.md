# 10.449. Добавление нового оборудования на склад без отдельного receipt-workflow

## Решение

Для MVP не вводится отдельный полноценный workflow `receipt` с отдельной процедурой приёмки, поставщиками, зонами приёмки и связанными WMS-сущностями.

При этом любое увеличение физического складского остатка должно происходить только через явную типизированную складскую операцию `stock_addition` и не может быть прямым редактированием `on_hand`.

## Новая номенклатурная позиция

При создании новой позиции каталога пользователь может сразу указать начальное количество.

Снаружи это может выглядеть как одно действие, но внутри система должна выполнить два логически разделённых шага:

1. создать номенклатурную позицию в `catalog`;
2. создать неизменяемую `WarehouseOperation` типа `stock_addition`, увеличивающую `on_hand` в `inventory` на указанное количество.

Если начальное количество равно нулю, операция `stock_addition` не требуется.

## Уже существующая позиция

Для существующей позиции используется отдельное складское действие уровня UI, например `Добавить на склад`.

Минимальные данные операции:

- позиция;
- добавляемое количество;
- исполнитель;
- время;
- короткое основание/комментарий, например `Куплено 4 шт.`.

После успешной операции `inventory` увеличивает `on_hand`.

## Архитектурные правила

- `stock_addition` использует общий неизменяемый `WarehouseOperation` envelope из 10.433;
- операция не является прямым CRUD-изменением баланса;
- `catalog` владеет карточкой номенклатуры, а `inventory` — физическим количеством;
- ошибочное добавление не редактируется задним числом и исправляется новой корректирующей/компенсирующей операцией;
- отдельный расширенный `receipt` workflow может быть добавлен позднее без изменения базового правила о том, что остаток изменяется только через явные операции.

## Связь с 10.448

Это решение уточняет 10.448.

Фраза `в MVP нет отдельного receipt` означает отсутствие отдельного сложного процесса приёмки, но не означает возможность напрямую записать новое значение остатка.

Канонический MVP-путь увеличения остатка — `stock_addition`.
