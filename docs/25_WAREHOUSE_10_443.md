# 10.443. Недостача при возврате оформляется как отдельное складское исключение

## Решение

При возврате оборудования разница между ранее выданным и фактически возвращённым количеством **не создаёт `ShortageCase` автоматически**.

Такое событие фиксируется как отдельное складское исключение/расхождение типа `missing` в контуре `warehouse-operations` / `inventory`.

`ShortageCase` создаётся или увеличивается только тогда, когда после учёта фактического состояния склада доступного пригодного количества действительно недостаточно для уже подтверждённой потребности проекта.

## Канонический смысл

Нужно разделять два разных понятия:

- `missing` — физическое складское расхождение: часть ранее выданного имущества не вернулась;
- `ShortageCase` — неудовлетворённая потребность проекта из-за недостатка реально доступного запаса.

Это разные доменные события и они не должны быть одной сущностью.

## Пример

Было выдано 10 единиц, вернулось 9.

Система фиксирует `missing = 1` для конкретной складской операции возврата.

Если после этого на складе всё ещё достаточно `Ready`-остатка для всех подтверждённых резервов, `ShortageCase` не создаётся.

Если доступного запаса становится недостаточно, `shortages` отдельно формирует или увеличивает `ShortageCase` на фактически непокрытое количество.

## Архитектурные границы

- `warehouse-operations` фиксирует факт возврата и расхождение;
- `inventory` отражает фактическое состояние запаса;
- `reservations` продолжает владеть подтверждённой потребностью;
- `shortages` создаёт кейс только из реального дефицита обеспечения, а не из самого факта складского расхождения;
- серийный номер может использоваться для идентификации конкретной пропавшей единицы, если это необходимо, но обычный резерв по-прежнему не связан с серийниками.

## Инвариант

Складское расхождение не равно дефициту проекта.

`missing` может привести к `ShortageCase`, но не является им автоматически.
